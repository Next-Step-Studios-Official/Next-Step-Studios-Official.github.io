## 1. Purpose

This policy describes how updates to Places Left Behind would be handled: what an update is, how it is delivered, what it may change, how saves and modifications are affected, and what is not promised.

It is written to set expectations honestly. An independent game in early development cannot promise a fixed patch cadence.

## 2. No Guaranteed Update Schedule

1. The owner does not commit to a release cadence, a patch schedule, or a number of updates.
2. No update is promised by this policy or by the game's marketing. Any roadmap is indicative and may change.
3. The owner may stop updating the game at any time, subject to section 9.

## 3. What an Update May Include

- Defect fixes.
- Performance and stability improvements.
- Compatibility fixes for new hardware, drivers, or operating systems.
- Content additions, including new locations, documents, photographs, or evidence.
- Changes to systems, controls, interface, or balance.
- Removal or replacement of features.
- Security fixes.
- Changes to third-party components and their notices.

An update may change the game materially. It may change how existing content plays.

## 4. How Updates Are Delivered

1. Through the distribution platform or storefront that supplied the game.
2. Through the studio's own download page, if the game was sold directly.
3. Through a launcher, if a launcher is introduced and the launcher terms are adopted.

Delivery mechanisms vary. The owner is not responsible for a platform's delivery failures, but should assist where reasonable.

## 5. Automatic Updates and Offline Use

1. On platforms that update automatically, a new version may install without explicit action.
2. The game is intended to be playable offline once installed. Whether an update check requires a connection depends on the platform and would be disclosed.
3. A user who does not update may be unable to use features that depend on a newer version. Save compatibility is not guaranteed across versions.

## 6. Save Data Compatibility

1. Updates may change the save format.
2. Where practical, the owner would aim to preserve compatibility or to migrate old saves.
3. Compatibility is not guaranteed. A save made in an older version may become unusable.
4. Users are encouraged to back up saves. The owner is not liable for lost saves or progress.
5. Save location and format are described in the [Game Save Data and User Data Policy](/docs/places-left-behind/game-save-data-policy).

**Current status:** saving is not implemented, so no save compatibility policy can yet be exercised.

## 7. Modifications and Updates

1. A modification built for one version may break after an update.
2. The owner is not obliged to preserve compatibility with modifications, to delay an update for a modification, or to support a modified installation.
3. Where modding is supported in future, the modding terms would state the compatibility expectations. See [`../Modding/Mod-Distribution-Policy.md`](/docs/places-left-behind/mod-distribution-policy).
4. Support may be declined where a modification is installed, and the user may be asked to reproduce an issue on an unmodified installation.

## 8. Patch Notes and Communication

1. The owner would publish patch notes describing significant changes, including changes that affect saves or modifications.
2. Patch notes may be published on the studio's website, in the distribution platform's update feed, or in both.
3. Security fixes may be described in general terms until users have had a reasonable opportunity to update.

## 9. End of Support

1. The owner may end support for the game or for a particular version.
2. Where support ends, the owner should state that it has ended rather than leaving users to infer it.
3. Ending support does not remove the user's licence to use the copy they obtained, subject to the end-user terms and to the platform's rules.
4. Ending support does not create a right to a refund, except where required by law or by the store's policy.

## 10. Updates to Third-Party Components

An update may add, remove, or change a third-party component. When that happens:

1. The dependency inventory must be updated. See [`../ThirdParty/Third-Party-Licenses.md`](/docs/places-left-behind/third-party-licenses).
2. `THIRD-PARTY-NOTICES.txt` must be updated if a required notice changes.
3. The [Third-Party Redistribution Checklist](/docs/places-left-behind/third-party-redistribution-checklist) must be run again before the update ships.

## 11. Updates to Legal Documents

1. The end-user terms may be updated alongside a game update.
2. Material changes should be presented to the user, not buried in a patch note.
3. A change to the terms does not retroactively alter the terms that applied to a copy already licensed, unless the user accepts it or the law requires otherwise.

## 12. No Warranty Arising From Updates

Providing an update does not create a warranty that further updates will follow, that a defect will be fixed, or that the game will remain compatible with any particular system. The warranty and liability position is in the [Game Warranty and Liability Notice](/docs/places-left-behind/game-warranty-and-liability).

## 13. Open Items Requiring Confirmation

- Whether updates will be mandatory or optional on the chosen platform.
- Whether a launcher will be used, and what update behaviour it would have.
- Whether any specific update commitment should be made publicly.
- How save migration would be implemented and tested before release.
- Whether a public roadmap is appropriate, and how to avoid implying a guarantee.
