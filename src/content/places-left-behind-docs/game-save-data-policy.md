## 1. Purpose

This policy describes how save data and other user data stored on the player's device are intended to work: where they live, what they contain, who controls them, and what happens on update, modification, or uninstall.

## 2. Current Status — Verified

- No save system is implemented. `Source/Game/Saving/` contains only a placeholder.
- The game writes no files.
- The game reads `Configuration/game.settings.json` from its installation directory.
- The game reads compiled shaders from its `Shaders` directory.
- No cloud save, no account, and no synchronisation exist.

Anything below describing saves is a design intention, not an implemented feature.

## 3. Intended Save Location

Save data is intended to be stored in the user's local application-data directory, not inside the installation folder.

Reasons:

- installation folders may be protected or read-only;
- an update or reinstall should not destroy progress;
- uninstalling should not silently delete saves without the user's knowledge;
- different Windows users on one machine should have separate progress.

The exact folder, file naming, and format are undecided. When chosen, they must be documented here and in the game's player-facing documentation.

## 4. Intended Save Contents

Save data is expected to record:

- the player's position and orientation in a location;
- which locations have been visited and their state;
- collected documents and evidence;
- photographs taken and their associated clues;
- investigation progress and discovered facts;
- equipment preparation state at the home base;
- settings that are part of the player's profile rather than the machine.

Save data should not contain:

- personal identifiers;
- account credentials;
- hardware identifiers;
- anything not needed to restore progress.

No save data is transmitted. There is no server to transmit it to.

## 5. Ownership and Control

- Save files are the player's data, stored on the player's device.
- The owner does not claim ownership of a player's save file content.
- The player may back up, copy, or delete their own save files.
- Save files are not a licensed work product distributed by the owner; they are generated by the player's use of the game.
- The owner may publish a save format description, but is not obliged to.

## 6. Backup and Data Loss

- The player is responsible for backing up saves.
- The owner is not liable for lost or corrupted saves, including loss caused by a crash, an update, a modification, or an operating-system failure.
- The owner should aim to warn players before an update that breaks save compatibility.

## 7. Save Compatibility Across Versions

- Save formats may change during development and after release.
- Where practical, older saves would be migrated automatically.
- Compatibility is not guaranteed. A version may refuse to load an older save rather than risk corrupting it.
- Prototype saves should be assumed to be disposable.

## 8. Cloud Saves

No cloud save feature exists and none is planned for the initial release.

If cloud saves are added later:

- their behaviour, storage location, and provider must be documented;
- a privacy update would be required, because save data would leave the device;
- the player must be able to opt out and to delete cloud data;
- any platform-provided cloud save must be described accurately.

## 9. Modifications and Save Data

- A modification may change save data in ways the game does not expect.
- The owner is not responsible for saves corrupted by a modification.
- Support may be declined where a modification is installed.
- If modding is supported in future, the modding terms should describe save interaction.

## 10. Settings and User Data

Settings data is intended to live either in the application-data directory or alongside the installation, depending on whether a setting is per-machine or per-player.

Settings contain no personal data. They may contain the player's chosen resolution, volume levels, and control bindings.

## 11. Uninstall and Deletion

- Uninstalling should remove the game files.
- Uninstalling should not silently delete saves; either saves are preserved, or the uninstaller clearly offers to remove them.
- The player can delete saves manually by removing the documented folder.
- No remote copy exists to delete when a player stops playing.

## 12. Screenshots and Recordings

Screenshots and recordings made by the player are stored by whatever tool the player uses, not by the game. The owner does not receive them. Sharing them publicly is covered by sections 8 and 9 of the [Prototype Distribution License](/docs/places-left-behind/prototype-distribution-license) and by section 11 of the [EULA](/docs/places-left-behind/eula-draft).

## 13. User Data Requested by the Owner

If a tester or player sends a save file to help diagnose a defect:

- it is used only to investigate that defect;
- it should be deleted once the matter is resolved;
- it may contain the player's progress, so it should not be published;
- the player should be told what it contains before sending it.

## 14. Implementation Checklist

When saving is implemented:

- [ ] Save path documented and implemented outside the installation folder.
- [ ] Save format versioned.
- [ ] Corrupt-save handling that does not crash the game.
- [ ] Clear error message when a save cannot be loaded.
- [ ] Uninstall behaviour decided and documented.
- [ ] Privacy policy updated if anything leaves the device.
- [ ] Save location added to player-facing documentation.
- [ ] Compatibility policy applied to updates.

## 15. Open Items Requiring Confirmation

- The exact save folder and file naming convention.
- Whether settings live with saves or separately.
- Whether a save format specification will be published.
- Whether any platform cloud save would be supported, and under what terms.
- Legal review of the ownership and liability statements.
