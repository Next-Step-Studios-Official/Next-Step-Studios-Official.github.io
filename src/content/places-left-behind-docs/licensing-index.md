## 1. What This Is

This folder is the licensing and legal foundation for Places Left Behind and its custom engine.

It does three things:

1. It states, in binding form, who owns the project and what rights exist. See [`../../LICENSE`](/docs/places-left-behind/#source-only-files) and [`../../Source/Engine/LICENSE`](/docs/places-left-behind/#source-only-files).
2. It records, accurately, the third-party software and assets the project uses. See [`ThirdParty/Third-Party-Licenses.md`](/docs/places-left-behind/third-party-licenses) and [`../../THIRD-PARTY-NOTICES.txt`](/docs/places-left-behind/#source-only-files).
3. It prepares — as drafts — the agreements the project will need if it distributes prototypes, releases the game, supports modding, or accepts contributions.

**Most documents here are not in force.** The status field of each tells you which is which. Do not treat a draft as an agreement, and do not tell anyone that they have accepted terms they have not.

## 3. Status Labels

| Status | Meaning |
| --- | --- |
| **Current** | Describes existing ownership or verified practice. Accurate now. |
| **Draft** | Complete proposed terms. Not adopted, not signed, not in force. |
| **Future Draft** | Prepared for a planned feature that does not exist yet. |
| **Requires Verification** | A fact or licence that could not be confirmed. Must be resolved before reliance. |
| **Requires Legal Review** | Custom legal terms that need a qualified lawyer before use. |

A document can carry both a Draft status and a Requires Legal Review status. That combination is the normal state for custom agreements at this stage.

**Creating a document does not make it current.** Status reflects reality, not effort.

## 6. The Licensing Boundaries, in One Page

| Component | Licensing position | Can it change separately? |
| --- | --- | --- |
| Game code (`Source/Game/`) | Proprietary, all rights reserved | Yes |
| Engine code (`Source/Engine/`) | Proprietary, all rights reserved | Yes — this is the point of the separation |
| Original assets (`Assets/`) | Proprietary, all rights reserved | Yes |
| Documentation (`Documentation/`) | Proprietary, not open-source licensed | Yes |
| Third-party software | Upstream licences (MIT, zlib) | No — fixed by upstream |
| Third-party creative assets | None present; would be per-asset | Per asset |
| Community mods | Authors keep ownership | N/A — no system exists |

What is true today:

- **No open-source licence is applied anywhere in this repository.**
- The engine and game are licensed separately, so the engine can be relicensed independently in future. See [`Engine-Licensing.md`](/docs/places-left-behind/engine-licensing).
- The repository is private, and its visibility is not a licence. See section 4 of [`LICENSE.md`](/docs/places-left-behind/#source-only-files).
- No agreement here has been adopted or signed by anyone.

## 7. Versioning Rules

1. Every document starts at **version 1.0**.
2. A material change increments the minor version (1.0 → 1.1) and is recorded in that document's revision history.
3. A change that alters rights or obligations increments the major version (1.x → 2.0).
4. Typo and link fixes may be made without a version change, but must not alter meaning.
5. The website's published version must match the repository document's version.
6. Paired plain-text and Markdown license files must be revised together and must contain the same terms.

All documents in this system were created at version 1.0 in 2026.

## 8. Keeping Paired Files in Sync

Three license files exist in two formats each:

| Plain text | Markdown |
| --- | --- |
| `LICENSE` | `LICENSE.md` |
| `Source/Engine/LICENSE` | `Source/Engine/LICENSE.md` |
| `Source/Game/LICENSE` | `Source/Game/LICENSE.md` |

Rules:

1. Edit both in the same change.
2. The Markdown version carries a metadata table for convenience; the terms must be identical.
3. If they ever differ, both are wrong until corrected. Neither version silently wins.
4. `Documentation/Licensing/Project-Licensing.md` names both as the authoritative project license.

## 9. Common Tasks

**Adding a dependency**
Read [`ThirdParty/Third-Party-Compliance-Policy.md`](/docs/places-left-behind/third-party-compliance-policy), verify the licence from the package metadata, inspect the package for native binaries, then update the inventory and `THIRD-PARTY-NOTICES.txt`.

**Adding an asset**
Read [`Assets/Asset-Acquisition-Guidelines.md`](/docs/places-left-behind/asset-acquisition-guidelines), add a register entry first, and do not commit an asset whose licence is unverified.

**Preparing a build**
Run [`Compliance/Build-Packaging-Checklist.md`](/docs/places-left-behind/build-packaging-checklist) and [`Compliance/Third-Party-Redistribution-Checklist.md`](/docs/places-left-behind/third-party-redistribution-checklist). A build cannot be distributed until the terms it relies on are actually in force.

**Accepting a contribution**
Do not. Read [`Contributors/Contributor-Policy.md`](/docs/places-left-behind/contributor-policy) first.

**Publishing policies to the website**
Read [`Website-Policy-Integration.md`](/docs/places-left-behind/website-policy-integration). Drafts must not be published as active.

## 10. Facts Verified While Building This System

- The repository had no license file before this task.
- No open-source licence is applied anywhere in the repository.
- Direct dependencies: six Silk.NET 2.23.0 packages. Transitive: five more Silk.NET packages, `Ultz.Native.GLFW` 3.4.0 (zlib, ships GLFW), and two Microsoft MIT packages. Build-only: `Microsoft.NET.ILLink.Tasks` (MIT).
- No copyleft, non-commercial, or no-derivatives dependency is present.
- The .NET 10 runtime is a prerequisite, not redistributed by a framework-dependent publish.
- The game contains no network code, no telemetry, no accounts, and no save system. It reads its own configuration and compiled shaders and writes nothing.
- No third-party creative asset is present; the four recommended fonts have not been downloaded.
- `TestMap.blend`, `TestMap.glb`, `clear.vert`, and `clear.frag` are original project assets.
