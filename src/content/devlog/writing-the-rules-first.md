---
title: Writing the rules before the product
date: 2026-11-07
summary: The documentation package for the Discord bot came first — seven public policies and a set of internal registers, all version 0.2.0 and all still drafts.
tags: [policies, bot]
series: Foundations
---

Most projects write their policies at the end, usually because a platform asks for a
privacy policy URL and something has to be produced quickly. This one went the other way
round. Before the Bot is treated as finished, the Studio wrote down what it does with
information, who can see it, and where it lives.

That produced seven public documents — terms, privacy, acceptable use, community
guidelines, moderation, data retention, and a security overview — plus internal material:
a data and feature register, a release-readiness checklist, a security policy and an
incident response plan.

None of it is in force yet. Every public document is marked version 0.2.0, draft for
review, not yet effective. That labelling is deliberate: a policy that describes
behaviour nobody has verified is a promise the project cannot keep yet.

The useful side effect is that each document now has to earn its claims against the
actual code and database. Where the implementation is unknown, the document says so
instead of smoothing it over.
